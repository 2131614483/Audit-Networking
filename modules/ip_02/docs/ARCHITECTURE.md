### 2.3 RAG检索系统

#### 2.3.1 多路检索

```
用户输入（问询问题） → 查询理解 → 多路并行检索 → 重排序 → 结果输出
```

| 检索方式 | 技术方案 | 特点 |
|----------|----------|------|
| 语义检索 | text-embedding-3 + FAISS | 理解语义相似性 |
| 关键词检索 | Elasticsearch BM25 | 精确匹配 |
| 结构化检索 | 按行业/板块/问题类型过滤 | 精准筛选 |
| 混合检索 | RRF融合 | 综合排序 |

#### 2.3.2 检索优化

- **查询扩展**：基于LLM的问询问题语义扩展
- **行业限定**：优先检索同行业案例
- **时效性权重**：近期案例权重更高
- **相似度阈值**：低于阈值的案例不返回
- **多样性保证**：避免返回过于相似的案例

### 2.4 LLM回复生成

#### 2.4.1 回复生成流程

```
问询问题 → 案例检索 → 相似案例 → LLM生成 → 数据填充 → 质量检查 → 回复初稿
                                    ↑
                              审计底稿数据
```

#### 2.4.2 生成能力

| 生成类型 | 输入 | 输出 |
|----------|------|------|
| 回复初稿 | 问询问题+相似案例+公司数据 | 完整的回复初稿 |
| 审核要点分析 | 问询问题+历史案例 | 监管审核关注点分析 |
| 数据支撑建议 | 问询问题+公司数据 | 需要补充的数据和建议来源 |
| 回复策略建议 | 问询问题+历史结果 | 最佳回复策略建议 |
| 风险提示 | 问询问题+回复初稿 | 可能被追问的风险点 |

#### 2.4.3 回复结构

每份回复自动生成标准结构：

```
1. 问题概述：简要复述监管问询问题
2. 公司回复：核心回复内容
3. 数据支撑：相关数据和证据
4. 核查程序：已执行的核查程序
5. 核查结论：审计师的核查结论
6. 参考案例：参考的历史案例（如有）
```

### 2.5 质量检查

#### 2.5.1 自动检查

| 检查维度 | 检查内容 | 检查方法 |
|----------|----------|----------|
| 完整性 | 是否回答了所有问询要点 | LLM比对+规则检查 |
| 一致性 | 与招股书、底稿数据是否一致 | 数据交叉验证 |
| 合规性 | 是否符合监管回复要求 | 格式和内容规则检查 |
| 充分性 | 证据和数据是否充分 | 数据支撑度评估 |
| 风险点 | 是否存在被追问的风险 | 历史追问模式匹配 |

#### 2.5.2 审核流程

```
自动生成 → AI质量检查 → 审计人员审核 → 修改完善 → 终审发布
                                    ↓
                            不通过则返回修改
```
