### 2.2 模块详细设计

#### 2.2.1 LLM代码审查引擎

LLM代码审查引擎是方案的核心组件，利用大语言模型的深度代码理解能力进行智能审计。

**技术选型**：
- 基础模型：GPT-4/Claude-3/CodeLlama-34B（根据场景选择）
- 微调策略：基于安全审计数据集进行LoRA微调
- 部署方式：私有化部署（敏感代码不外传）

**功能设计**：

| 功能 | 说明 | 输入 | 输出 |
|------|------|------|------|
| 代码安全审查 | 检测OWASP Top10/CWE Top25安全漏洞 | 代码文件/PR Diff | 漏洞列表（含位置/类型/严重度） |
| 业务逻辑分析 | 检测业务逻辑缺陷 | 代码+业务描述 | 逻辑缺陷列表 |
| 合规检查 | 检查代码合规性（PCI-DSS/GDPR/SOX） | 代码+合规标准 | 不合规项列表 |
| 修复建议生成 | 自动生成安全修复代码 | 漏洞描述 | 修复代码片段 |
| 代码质量评估 | 评估代码可维护性/复杂度 | 代码文件 | 质量评分+改进建议 |

**LLM Prompt设计**：

#### 2.2.2 SAST扫描引擎

SAST扫描引擎作为基础检测层，提供快速、大规模的语法级安全扫描。

**技术选型**：
- 主引擎：SonarQube（代码质量+基础安全）
- 深度扫描：CodeQL（精确安全分析）
- 规则引擎：Semgrep（自定义规则）

**支持的编程语言**：Java、Python、JavaScript/TypeScript、C/C++、C#、Go、Rust、PHP、Ruby、Swift、Kotlin

**扫描策略**：
- **全量扫描**：每日/每周全量代码扫描
- **增量扫描**：PR/MR提交时增量扫描
- **定向扫描**：指定目录/文件的高精度扫描

#### 2.2.3 安全知识图谱

知识图谱用于沉淀和关联安全审计知识。

**实体类型**：
- 漏洞类型（CWE条目）
- 攻击模式（CAPEC条目）
- 技术栈（语言/框架/库）
- 修复模式（代码片段/最佳实践）
- 项目模块
- 审计发现

**关系类型**：
- 漏洞类型 → 影响 → 技术栈
- 攻击模式 → 利用 → 漏洞类型
- 修复模式 → 修复 → 漏洞类型
- 审计发现 → 属于 → 漏洞类型
- 审计发现 → 关联 → 项目模块

**图数据库**：Neo4j

#### 2.2.4 业务逻辑缺陷检测模块

**检测技术**：
- **代码流分析**：LLM分析代码执行路径，检测逻辑异常
- **状态机建模**：从代码中提取状态转换，检测非法状态转换
- **权限路径分析**：分析访问控制逻辑，检测权限绕过
- **交易完整性分析**：检测事务的一致性和原子性保障

**典型业务逻辑缺陷**：
- 水平越权（用户A访问用户B的数据）
- 垂直越权（普通用户执行管理员操作）
- 参数篡改（价格、数量等敏感参数未校验）
- 竞争条件（Race Condition）
- 状态绕过（跳过关键业务步骤）
- 重放攻击（请求可被重复执行）

#### 2.2.5 合规检查模块

**支持的合规标准**：
- PCI-DSS（支付卡行业数据安全标准）
- GDPR（通用数据保护条例）
- SOX（萨班斯-奥克斯利法案）
- HIPAA（健康保险可携性和责任法案）

**检查内容**：
- 敏感数据处理（加密/脱敏/日志记录）
- 认证机制强度
- 会话管理安全
- 输入验证完整性
- 错误处理安全
