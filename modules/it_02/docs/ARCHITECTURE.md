### 2.2 模块详细设计

#### 2.2.1 规则引擎

规则引擎是配置合规检查的核心，负责加载和执行合规检查规则。

**技术选型**：Drools（企业级）/ EasyRules（轻量级）

**功能设计**：
- **规则加载**：从规则库动态加载合规检查规则，支持规则版本管理
- **规则执行**：对采集的配置数据执行规则匹配，输出合规判定结果
- **规则编排**：支持规则优先级、依赖关系和执行顺序编排
- **规则测试**：提供规则沙箱环境，支持规则编写和测试

**规则示例**（CIS Benchmark for Linux）：
```
规则ID: CIS-1.1.1
规则名称: 确保文件系统分区配置正确
检查命令: mount | grep -E '^(/dev|tmpfs)'
合规条件: /tmp 分区包含 noexec,nosuid 挂载选项
严重级别: 高
```

#### 2.2.2 ML分析引擎

ML分析引擎提供智能配置异常检测和预测能力。

**模型组件**：

| 模型 | 算法 | 用途 | 训练数据 |
|------|------|------|---------|
| 配置异常检测 | Isolation Forest | 检测偏离正常范围的配置 | 历史配置快照 |
| 配置漂移预测 | Prophet/LSTM | 预测配置漂移趋势 | 配置变更历史 |
| 配置相似度 | Siamese Network | 相似系统配置比对 | 多系统配置数据 |
| 误报降噪 | XGBoost | 降低规则引擎误报率 | 人工审核历史 |

**异常检测流程**：
1. 采集系统配置快照
2. 特征提取（配置项编码、数值归一化）
3. Isolation Forest异常评分
4. 异常阈值判定（动态阈值基于统计分布）
5. 异常解释生成（SHAP值分析）

#### 2.2.3 合规评分引擎

**评分模型**：
- **单系统评分**：基于通过的规则占比和严重级别加权
- **部门评分**：下属系统评分的聚合
- **企业评分**：全局合规健康度

**评分公式**：
```
合规评分 = Σ(通过规则权重) / Σ(总规则权重) × 100
权重分配：严重(5) > 高(3) > 中(2) > 低(1)
```

#### 2.2.4 配置差异引擎

**功能**：
- 配置版本快照管理（每次扫描自动创建快照）
- 配置变更差异对比（可视化Diff展示）
- 配置漂移趋势分析（时间维度展示配置变化）
- 漂移根因分析（关联变更事件和操作记录）

#### 2.2.5 修复建议引擎

**功能**：
- 自动生成不合规项的修复脚本
- 修复优先级排序（基于风险和影响范围）
- 修复验证（修复后自动复检）
- 修复知识库（历史修复方案沉淀）
