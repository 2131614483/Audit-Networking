### 2.3 RAG检索系统

#### 2.3.1 检索架构

```
用户查询 → 查询理解 → 多路检索 → 融合排序 → 结果返回
```

**多路检索策略：**

| 检索方式 | 技术方案 | 权重 |
|----------|----------|------|
| 语义检索 | text-embedding-3 + FAISS | 40% |
| 关键词检索 | Elasticsearch BM25 | 30% |
| 结构化过滤 | 按行业/板块/问题类型 | 20% |
| 知识图谱检索 | Cypher查询 | 10% |

#### 2.3.2 检索增强

- **查询改写**：基于LLM将自然语言问题改写为检索查询
- **查询扩展**：同义词扩展、相关概念扩展
- **多轮检索**：首轮粗筛后根据结果进行第二轮精筛
- **相关性反馈**：基于用户点击和反馈优化排序

### 2.4 LLM智能问答

#### 2.4.1 问答能力

| 问题类型 | 示例 | 回答方式 |
|----------|------|----------|
| 案例查询 | "有哪些科创板公司被问询了收入确认问题？" | 检索+列表 |
| 对标分析 | "我们这个行业上市公司的平均审核周期是多少？" | 统计+分析 |
| 问题解答 | "关联交易定价公允性如何论证？" | 检索+总结 |
| 趋势分析 | "今年监管对研发费用资本化的态度有什么变化？" | 分析+总结 |
| 风险提示 | "我们这个案例有哪些可能被问询的风险点？" | 分析+建议 |

#### 2.4.2 回答质量保障

- **引用来源**：所有回答标注案例来源和链接
- **置信度标注**：标注回答的可信度
- **时效性标注**：标注数据的统计时间范围
- **免责声明**：AI辅助参考，专业判断不可替代

### 2.5 案例对标分析

#### 2.5.1 对标维度

| 对标维度 | 对标内容 | 分析方式 |
|----------|----------|----------|
| 行业对标 | 同行业案例的审核关注点 | 聚类分析+频次统计 |
| 板块对标 | 同板块的审核标准和要求 | 规则匹配+统计 |
| 问题对标 | 同类问题的处理方式 | 案例检索+总结 |
| 时间对标 | 不同时期的审核趋势变化 | 时序分析 |
| 结果对标 | 通过/否决案例的特征对比 | 对比分析 |

#### 2.5.2 对标报告

自动生成案例对标分析报告：

```
1. 行业概况：同行业IPO审核概况
2. 关注点分析：监管对本行业的常见关注点
3. 问题对标：类似问题的处理案例
4. 审核周期：行业平均审核周期
5. 通过率：行业审核通过率
6. 风险提示：基于对标的潜在风险提示
7. 建议：基于对标的审计建议
```
