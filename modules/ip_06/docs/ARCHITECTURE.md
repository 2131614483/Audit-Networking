```
问题描述 → LLM分析 → 根因识别 → 影响评估 → 分析报告

- **5Why分析**：自动进行5Why根因分析

### 2.3 整改方案推荐

#### 2.3.1 方案生成

**输入：** 问题描述 + 根因分析 + 企业特征 + 行业特征

**生成流程：**

```
问题诊断 → 方案检索 → 相似方案 → LLM生成 → 定制化调整 → 方案输出
```

**方案结构：**

```
整改方案 = {
  问题: "收入确认时点不当",
  根因: "销售合同中验收条款不明确",
  整改目标: "规范收入确认流程",
  具体措施: [
    "1. 修订标准销售合同模板，明确验收条款",
    "2. 建立收入确认审批流程",
    "3. 对财务人员进行新收入准则培训",
    ...
  ],
  责任部门: "财务部、销售部",
  完成时限: "30天",
  验证方式: "抽查30笔收入确认记录",
  预期效果: "收入确认合规率100%"
}
```

### 2.4 ML效果预估

#### 2.4.1 预估模型

| 预估维度 | 模型 | 输入特征 |
|----------|------|----------|
| 实施难度 | XGBoost回归 | 措施数量、涉及部门、资源需求、时间要求 |
| 成功概率 | LightGBM分类 | 问题类型、方案复杂度、企业执行力、历史成功率 |
| 实施周期 | XGBoost回归 | 措施数量、依赖关系、资源约束 |
| 成本估算 | 线性回归+规则 | 人力成本、外部咨询、系统改造 |
| 效果评分 | 多任务学习 | 问题解决程度、复发概率、长期影响 |

#### 2.4.2 方案评分

```
方案评分 = 效果评分 × 权重1 + 可行性评分 × 权重2 + 成本效益比 × 权重3
```

| 评分区间 | 推荐等级 | 含义 |
|----------|----------|------|
| ≥85分 | 强烈推荐 | 方案效果好，可行性高 |
| 70-84分 | 推荐 | 方案可行，效果较好 |
| 50-69分 | 可选 | 方案有一定可行性 |
| <50分 | 不推荐 | 方案可行性或效果不足 |

### 2.5 优先级排序

#### 2.5.1 排序因素

| 因素 | 权重 | 评估方式 |
|------|------|----------|
| 问题严重程度 | 30% | 对财务报表影响、对上市影响 |
| 整改紧迫性 | 25% | 时间敏感度、审核节点要求 |
| 整改难度 | 15% | 资源需求、实施复杂度 |
| 效果确定性 | 15% | 方案成功概率、效果可预期性 |
| 依赖关系 | 15% | 是否其他问题解决的前提 |

```

1. [高优先级] 收入确认流程缺陷 → 30天内完成

4. [低优先级] 财务人员培训不足 → 90天内完成
