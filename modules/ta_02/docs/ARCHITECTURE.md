### 2.2 模块详细设计

#### 2.2.1 四单匹配逻辑

**匹配维度**：

| 匹配维度 | PO-GR | GR-IV | IV-Payment |
|---------|-------|-------|-----------|
| 数量 | ✓ | ✓ | - |
| 金额 | ✓（单价） | ✓（总价） | ✓ |
| 税率 | - | ✓ | - |
| 供应商 | ✓ | ✓ | ✓ |
| 物料/商品 | ✓ | ✓ | - |
| 采购单号 | ✓ | ✓ | ✓ |
| 合同号 | ✓ | - | - |

**匹配模式**：

| 模式 | 说明 | 处理策略 |
|------|------|---------|
| 1:1 | 一张PO对应一张GR/IV | 直接匹配 |
| 1:N | 一张PO分批到货/开票 | 分批匹配+累计校验 |
| N:1 | 多张PO合并开票 | 合并匹配+分摊 |
| N:M | 多张PO、多张GR/IV | 复杂匹配+AI推荐 |

#### 2.2.2 ML匹配决策模型

**模型选型**：XGBoost / LightGBM

**特征工程**：

| 特征类别 | 特征 | 说明 |
|---------|------|------|
| 数量特征 | 数量差、数量差比例、累计数量 | PO数量vs发票数量 |
| 金额特征 | 金额差、金额差比例、单价差 | PO金额vs发票金额 |
| 时间特征 | 时间差（PO-GR-IV间隔） | 时间合理性判断 |
| 文本特征 | 商品描述相似度（NLP） | 商品名称模糊匹配 |
| 供应商特征 | 供应商历史匹配率、异常率 | 供应商信用评估 |
| 单据特征 | 单据类型、币种、税率一致性 | 基础合规检查 |

**模型输出**：
- 匹配分类：匹配/不匹配/待确认
- 置信度评分：0-100
- 异常类型：数量差异/价格差异/税率差异/供应商不一致等
- 推荐动作：自动匹配/人工审核/退回修改

#### 2.2.3 异常处理推荐模型

**异常分类**：

| 异常类型 | 占比 | 处理建议 | 自动处理 |
|---------|------|---------|---------|
| 数量差异（合理范围） | 30% | 按实际数量匹配 | 可自动 |
| 价格差异（价格波动） | 20% | 按合同价格或发票价格 | 条件自动 |
| 税率差异 | 10% | 按正确税率调整 | 需人工 |
| 分批到货/开票 | 15% | 累计匹配 | 可自动 |
| 折扣/返利处理 | 5% | 按约定折扣处理 | 条件自动 |
| 供应商不一致 | 5% | 退回确认 | 需人工 |
| 其他异常 | 15% | 人工判断 | 需人工 |

#### 2.2.4 NLP商品描述匹配

**技术选型**：
- 中文分词：Jieba / HanLP
- 文本嵌入：BERT-whitening / Sentence-BERT
- 相似度计算：余弦相似度 + 编辑距离

**应用场景**：
- 商品名称的模糊匹配（"笔记本电脑" vs "笔记本计算机"）
- 商品规格的语义匹配
- 不同系统间商品描述的归一化

#### 2.2.5 规则引擎

**规则类型**：

| 规则类型 | 示例 | 优先级 |
|---------|------|--------|
| 硬性规则 | PO号必须一致 | 最高 |
| 金额规则 | 发票金额≤PO金额×1.1 | 高 |
| 数量规则 | 发票数量≤GR数量 | 高 |
| 时间规则 | 发票日期≥GR日期 | 中 |
| 供应商规则 | 发票供应商=PO供应商 | 高 |
