### 2.2 合规要求提取流程

#### 2.2.1 从法规文本到结构化要求

```
法规文本 → 结构化合规要求的转换流程：

Step 1: 法规文本预处理
  输入：法规全文（PDF/HTML/Word）
  处理：
  ├── 文本清洗（去除页眉页脚/水印/无关信息）
  ├── 结构解析（识别章节/条款/段落层级）
  └── 段落分割（按语义段落切分）

Step 2: 义务条款识别
  使用LLM识别包含合规义务的条款：
  关键词模式：
  ├── 强制性义务："应当" "必须" "不得" "禁止" "要求"
  ├── 条件性义务："在...情况下应当" "如...则必须"
  ├── 时间性义务："在...日内" "于...之前"
  └── 报告性义务："应当报告" "应当披露" "应当通知"

Step 3: 结构化提取
  对每个义务条款提取结构化信息：
  {
    "requirement_id": "REQ-001",
    "article_ref": "第12条",
    "requirement_text": "数据处理者应当建立数据泄露应急响应机制",
    "requirement_type": "制度要求",
    "subject": "数据处理者",
    "action": "建立数据泄露应急响应机制",
    "conditions": [],
    "deadline": "法规生效后90日内",
    "penalty": "违规处100万-500万元罚款",
    "related_requirements": ["REQ-002", "REQ-003"]
  }

Step 4: 要求去重与归类
  ├── 合并相同/相似要求
  ├── 归类至合规领域（数据隐私/反洗钱/反腐败等）
  └── 建立要求间的依赖关系

Step 5: 人工审核
  合规专家审核结构化要求列表
  修正LLM提取的错误/遗漏
  确认要求的准确性和完整性
```

### 2.3 RAG知识库设计

#### 2.3.1 知识库内容与检索

```
RAG知识库结构：

1. 历史评估案例库
   内容：500+份历史法规影响评估报告
   索引：按法规类型/行业/企业规模/评估时间
   用途：参考类似法规的评估方法和结论

2. 行业对标数据库
   内容：各行业合规最佳实践和基准
   索引：按行业/合规领域/企业规模
   用途：评估合规差距时参考行业水平

3. 监管处罚案例库
   内容：10,000+条全球监管处罚案例
   索引：按法规/地区/处罚金额/违规类型
   用途：量化违规风险和处罚预期

4. 合规解决方案库
   内容：针对常见合规要求的技术/流程解决方案
   索引：按要求类型/技术方案/实施难度
   用途：生成整改建议时参考可行方案

5. 企业内部合规状态库
   内容：企业现有政策/控制/系统/流程的合规映射
   索引：按业务单元/流程/系统
   用途：差距分析时比对当前状态

检索策略：
  ├── 语义检索：基于Embedding的向量相似度
  ├── 层级检索：先按法规类型→再按具体要求
  ├── 混合检索：语义+关键词+元数据过滤
  └── 排序策略：按相关性+时效性+权威性加权
```
