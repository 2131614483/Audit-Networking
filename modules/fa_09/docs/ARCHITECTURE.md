│ I013 │ 底稿中的调整分录是否有支持依据                │ NLP语义  │

评分算法：
  完整性评分 = (已通过检查项 / 总检查项) × 100
  
  严重缺失（扣分项）：
  - 缺少审计结论：-20分
  - 缺少关键审计程序执行记录：-15分
  - 缺少编制人签字：-10分
  
  轻微缺失（扣分项）：
  - 缺少非关键字段：-2分/项
  - 格式不规范：-1分/项

  ≥ 90分：完整 ✅

### 2.3 逻辑一致性检查模块

```
逻辑一致性检查 — LLM+规则引擎

检查类型：

① 结论-证据一致性
  检查：审计结论是否得到审计证据的支持
  示例：
    底稿结论："应收账款可确认，坏账准备计提充分"
    但审计证据显示：客户A账龄3年以上余额¥500万，未单项计提
    → LLM判断：结论与证据不一致（坏账计提可能不充分）

② 程序-风险一致性
  检查：执行的审计程序是否与风险评估等级匹配
  示例：
    风险评估：应收账款为"高风险"科目（收入确认舞弊风险）
    但执行的程序仅为基础程序（未执行截止测试/期后收款测试）
    → LLM判断：审计程序与风险不匹配

③ 跨底稿一致性
  检查：同一事项在不同底稿中的描述和结论是否一致
  示例：
    底稿A1（货币资金）："已执行银行函证，回函相符"
    底稿A2（函证汇总）："银行函证回函率90%，3份差异处理中"
    → LLM判断：信息不一致，需确认

④ 异常事项处理逻辑
  检查：异常事项是否有合理的解释和处理
  示例：
    底稿标记"收入增长20%，远超行业平均5%"
    但未对增长原因进行分析说明
    → LLM判断：异常事项缺乏解释，需补充
