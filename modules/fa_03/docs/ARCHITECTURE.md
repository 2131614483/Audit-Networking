### 2.2 三区架构详解

#### 2.2.1 原始数据区（Raw Zone）

```
原始数据区设计

存储路径结构：
  /raw/{data_source}/{project_code}/{table_name}/{date}/
  
  示例：/raw/erp_sap/P2025001/gl_balance/2025-12-31/
  
  文件：part-00001-xxxx.parquet
         part-00002-xxxx.parquet
         ...

写入策略：
  - 一次性写入，永不修改（Immutable）
  - 数据按天分区（日期分区）
  - 每个数据源独立目录
  - 文件格式：Snappy压缩Parquet

数据保留：
  - 项目期间：完整保留
  - 项目结束后：压缩归档至冷存储（MinIO冷热分层）
  - 合规保留：7年（满足审计档案法规）
  - 到期自动清理：标记删除，30天后物理删除

安全策略：
  - 写入：仅数据接入服务（FA-01）有写入权限
  - 读取：项目组审计师只读
  - 加密：AES-256服务器端加密
  - 审计日志：所有读取操作记录（谁/何时/读了什么数据）
```

#### 2.2.2 标准化数据区（Standardized Zone）

```
标准化数据区设计

存储路径结构：
  /standardized/{standard_model_version}/{project_code}/{table_name}/
  
  示例：/standardized/v2.0/P2025001/core_gl_balance/
  
  格式：Delta Lake（提供ACID事务）

版本管理机制：
  ┌─────────────────────────────────────────────────────────┐
  │ 版本号  │ 时间戳                │ 变更说明              │
  ├─────────┼───────────────────────┼──────────────────────┤
  │ v1      │ 2025-02-01 10:00:00  │ 初始加载              │
  │ v2      │ 2025-02-05 14:30:00  │ 重新映射科目代码       │
  │ v3      │ 2025-02-10 09:15:00  │ 修复日期格式异常       │
  │ v4      │ 2025-02-15 16:00:00  │ 补充缺失的部门字段     │
  │ v5      │ 2025-02-20 11:00:00  │ 审计调整（重分类）     │
  └─────────────────────────────────────────────────────────┘

时间旅行（Time Travel）：
  SELECT * FROM core_gl_balance 
  VERSION AS OF 3
  -- 查询v3版本的数据
  
  SELECT * FROM core_gl_balance 
  TIMESTAMP AS OF '2025-02-10 09:15:00'
  -- 查询该时间点的数据

优势：
  - 审计师可随时回溯到任一历史版本
  - 支持版本间差异对比
  - 审计调整可独立版本化
  - 数据错误可回滚，不影响已完成的审计工作
```

#### 2.2.3 分析就绪区（Analytics Zone）

```
分析就绪区设计

预计算分析数据集：

① 科目趋势分析宽表
  包含：公司代码 + 科目代码 + 年度 + 月度
        + 本期发生额 + 期末余额 + 上年同期
        + 同比变动率 + 环比变动率
  用途：一键查询科目趋势，无需关联多表

② 行业对比分析数据集
  包含：公司代码 + 科目代码 + 行业基准值
        + 行业四分位值 + 行业均值 + 标准差
        + 公司偏离度
  用途：快速定位异常科目

③ 风险评估特征宽表
  包含：所有科目 + 风险指标（波动率/异常值数量/关联交易占比）
        + 历史风险标签 + ML预测风险评分
  用途：AI风险模型的特征输入

④ 审计调整追溯表
  包含：调整编号 + 底稿索引 + 调整前金额 + 调整后金额
        + 调整原因 + 调整人 + 调整时间 + 审批人
  用途：审计调整的全量追溯

刷新策略：
  - 科目趋势表：每日增量刷新
  - 行业对比表：每周全量刷新
  - 风险特征表：每项目初始化 + 增量更新
  - 调整追溯表：实时更新
```
