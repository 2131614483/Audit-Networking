### 2.2 联盟链网络设计

#### 2.2.1 网络拓扑

```
联盟链网络拓扑

参与方角色：
┌─────────────┬──────────────┬─────────────────────────────┐
│ 参与方       │ 节点类型      │ 权限说明                    │
├─────────────┼──────────────┼─────────────────────────────┤
│ 审计机构     │ Peer + CA    │ 发起函证、验证回函、查看存证  │
│ 银行A        │ Peer + CA    │ 接收函证、查询数据、签名回函  │
│ 银行B        │ Peer + CA    │ 同上                        │
│ 银行C        │ Peer + CA    │ 同上                        │
│ 监管机构     │ Peer（只读）  │ 监督审计函证全流程           │
│ 排序节点     │ Orderer      │ 交易排序、区块生成（多机构共享）│
└─────────────┴──────────────┴─────────────────────────────┘

通道设计：
  - 主通道（Main Channel）：所有参与方加入
    用于：函证请求广播、回函通知、状态更新
  - 私有通道（Private Channel）：审计机构+银行
    每个银行独立通道，保护账户隐私
    用于：账户数据查询、回函数据传输

共识机制：
  - Raft（推荐）：Crash Fault Tolerant
  - 排序节点：3-5个（奇数，来自不同机构）
  - 区块生成间隔：2秒
  - 区块大小：10MB（或1000笔交易）
```

#### 2.2.2 数字证书与身份管理

```
PKI身份管理体系

证书类型：
  ┌─────────────────────────────────────────────────────────┐
  │ ① TLS证书（网络通信加密）                               │
  │    用途：节点间gRPC通信加密                            │
  │    颁发：Fabric CA                                      │
  │                                                         │
  │ ② 签名证书（身份认证+交易签名）                         │
  │    用途：函证请求签名/回函签名/交易背书                  │
  │    颁发：各机构CA（交叉认证）                            │
  │                                                         │
  │ ③ TLS客户端证书（应用层访问）                           │
  │    用途：审计师/银行操作员登录应用                      │
  │    颁发：各机构CA                                      │
  └─────────────────────────────────────────────────────────┘

身份验证流程：
  审计师登录 → 出示签名证书 → CA验证 → 获取JWT Token
  → Token携带至每次API调用 → Fabric验证交易签名
  → 智能合约验证调用者角色权限

权限控制（ABAC）：
  - 审计师角色：发起函证、查看本机构函证、验证存证
  - 银行角色：查看本银行函证、生成回函
  - 监管角色：查看所有函证（只读）
  - 管理员角色：网络运维、节点管理
```
