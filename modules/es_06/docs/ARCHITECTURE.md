### 2.2 方法论知识图谱

#### 2.2.1 图谱结构

| 节点类型 | 示例 | 属性 |
|----------|------|------|
| 审计主题（Subject） | 碳排放审计、水资源审计 | 名称、行业、标准 |
| 审计程序（Procedure） | GHG排放量验证程序 | 步骤列表、方法、时长 |
| 审计步骤（Step） | 数据收集→数据验证→计算 | 序号、操作说明、输出 |
| 证据类型（Evidence） | 电费账单、排放监测记录 | 名称、来源、可靠性 |
| 底稿模板（Template） | 碳排放底稿V2.0 | 字段列表、格式 |
| 风险点（Risk） | 排放数据不完整 | 风险描述、控制措施 |
| 行业（Industry） | 制造业、金融业 | 行业特征、适用标准 |

#### 2.2.2 关系类型

| 关系 | 起始→终止 | 说明 |
|------|-----------|------|
| 适用 | Subject → Industry | 审计主题适用的行业 |
| 包含 | Subject → Procedure | 审计主题包含的程序 |
| 由...组成 | Procedure → Step | 程序由步骤组成 |
| 需要 | Step → Evidence | 步骤需要的证据 |
| 使用 | Procedure → Template | 程序使用的底稿模板 |
| 关联 | Subject → Risk | 审计主题相关的风险点 |

### 2.3 LLM方法论生成

#### 2.3.1 审计程序自动生成

**输入：** 审计对象特征（行业、规模、业务范围）、适用标准、审计目标

**生成流程：**

```
审计对象特征 → 意图识别 → 方法匹配 → 程序生成 → 质量检查 → 输出
                          ↓
                   知识图谱检索+案例检索
```

| 生成维度 | 说明 | 示例输出 |
|----------|------|----------|
| 审计范围 | 确定审计覆盖范围 | "覆盖Scope1/2/3排放，重点审核Scope1" |
| 审计目标 | 明确审计要达成的目标 | "验证排放数据的完整性和准确性" |
| 审计程序 | 详细审计步骤 | "1.收集能耗数据→2.验证数据完整性→..." |
| 样本选择 | 确定抽样方法和样本量 | "分层抽样，样本量100笔交易" |
| 时间安排 | 审计各阶段时间规划 | "数据收集2天→验证3天→报告1天" |

#### 2.3.2 证据收集清单生成

| 证据类别 | 自动生成内容 | 示例 |
|----------|-------------|------|
| 必需证据 | 审计必须获取的证据 | "电力消耗月度数据" |
| 推荐证据 | 建议获取的辅助证据 | "设备能效报告" |
| 可选证据 | 视情况获取的补充证据 | "行业对标数据" |
| 验证证据 | 用于交叉验证的证据 | "第三方审核报告" |

#### 2.3.3 底稿模板生成

- **模板结构**：基于审计主题自动确定底稿的章节结构
- **字段填充**：预填充已知信息（企业名称、审计期间、标准引用）
- **公式嵌入**：自动嵌入碳排放计算、指标计算等公式
- **格式标准化**：统一的底稿格式和样式

### 2.4 质量检查引擎

#### 2.4.1 方法论质量检查

| 检查维度 | 检查内容 | 检查方法 |
|----------|----------|----------|
| 完整性 | 是否覆盖所有必要的审计程序 | 与标准要求比对 |
| 一致性 | 与标准要求的一致性 | 规则引擎比对 |
| 可行性 | 审计程序是否可执行 | 时间/资源评估 |
| 风险覆盖 | 是否覆盖关键风险点 | 风险矩阵检查 |
| 行业适配 | 是否针对行业特点定制 | 行业特征匹配 |

#### 2.4.2 持续改进

- **执行反馈**：收集审计人员对生成方法论的反馈
- **效果评估**：评估生成方法论的审计效果（问题发现率、效率）
- **模型优化**：基于反馈和评估结果持续优化生成模型
- **知识更新**：定期更新知识图谱和最佳实践库

### 2.5 方法论管理

- **版本管理**：方法论版本控制，支持历史版本回溯
- **审批流程**：生成的方法论需经审核后正式发布
- **权限控制**：基于角色的访问和编辑权限
- **使用统计**：方法论使用频率、效果等统计分析
- **个性化配置**：支持审计团队自定义方法偏好
