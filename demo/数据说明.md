# 多模态模拟数据集说明

## 一、数据合规来源声明

### 1.1 数据性质

本数据集（位于 `demo/synthetic_data/`，总量 **1.072 GB / 1097 MB**）为**完全程序化生成的模拟数据**，不涉及任何真实企业、真实个人或真实交易记录。

- **生成方式**：通过 [demo/generate_synthetic_data.py](../demo/generate_synthetic_data.py) 使用 Python 标准库（`random` / `hashlib` / `datetime`）按预设模板和随机种子合成
- **生成时间**：2026-08-08
- **生成耗时**：91 秒
- **覆盖范围**：78 个审计模块，每个模块独立目录

### 1.2 合规声明

| 合规维度 | 声明 |
|---------|------|
| 真实企业数据 | ✗ 不含。公司名称（如"卓郎智能机械股份有限公司"）为虚构，与任何现实企业重名属巧合 |
| 真实个人数据 | ✗ 不含。人物姓名（如"王某""李某"）为脱敏化虚构代号 |
| 真实金融账户 | ✗ 不含。银行账号、统一社会信用代码（USCC）均为格式合法但校验位虚构的随机字符串 |
| 真实交易记录 | ✗ 不含。所有交易金额、流水号为随机生成，不对应任何真实交易 |
| 真实舆情文本 | ✗ 不含。文本语料由模板填充随机变量生成，非真实新闻报道或公告 |
| 个人信息保护 | ✓ 符合《个人信息保护法》。不含任何可识别自然人的真实信息 |
| 数据安全法 | ✓ 符合《数据安全法》。数据为非敏感模拟数据，可自由流转和公开 |
| 商业秘密 | ✓ 不涉及。无任何真实企业的商业数据 |

### 1.3 使用边界

- ✓ **允许**：用于本项目的模块功能验证、组网管道测试、算法演示、教学展示
- ✓ **允许**：在本项目内部跨模块流转、入湖存储、对齐处理
- ✗ **禁止**：将本数据集作为真实审计依据输出给最终用户
- ✗ **禁止**：将本数据集用于训练生产级 AI 模型（数据分布与真实业务存在偏差）

## 二、数据类型与模态

### 2.1 六大数据模态

本数据集覆盖六种数据模态，与 [contract.py](../modules/shared/contract.py) 的 `MODALITIES` 枚举严格对齐：

| 模态 | 代码枚举 | 文件格式 | 典型内容 | 对应 dtype |
|------|---------|---------|---------|-----------|
| 结构化表格 | `tabular` | `.jsonl` | ERP明细、台账、交易流水、发票 | `str` / `int` / `float` / `datetime` |
| 文本语料 | `text` | `.txt` | 财报摘要、舆情报道、合同条款、监管公告 | `str` |
| 图片引用 | `image` | `.jsonl` (blob_ref) | 票据扫描件、银行回单、卫星遥感图 | `blob` |
| 视频引用 | `video` | `.jsonl` (blob_ref) | 会议录像、监控片段 | `blob` |
| 时序数据 | `timeseries` | `.jsonl` | 行情、交易流水、碳排放、系统日志 | `datetime` + `float` |
| 图结构 | `graph` | `.json` | 知识图谱节点/边、关联方网络 | `dict` (嵌套) |

### 2.2 多模态引用存储（CAS 模型）

图片和视频采用**内容寻址存储（Content-Addressable Storage）**模型，数据库中仅存引用元数据，不存二进制内容：

```json
{
  "uri": "s3://audit-data/image/a3f8b2c1.jpg",
  "hash": "a3f8b2c1d5e6f7a8b9c0d1e2f3a4b5c6",
  "mime": "image/jpeg",
  "modality": "image",
  "size_bytes": 2456789,
  "captured_at": "2025-06-15T10:30:00",
  "description": "票据扫描件"
}
```

这与 [fa_03 数据湖](../modules/fa_03/engine.py) 的 ODS/DWD schema 中 `media_uri` / `media_hash` / `media_mime` / `media_modality` 字段对应。

### 2.3 文件格式与接口契约映射

数据文件格式与 [network_schema.json](../modules/shared/network_schema.json) 的 `format` 字段对齐：

| 数据文件 | 文件格式 | 契约 format | 用途 |
|---------|---------|------------|------|
| `*.jsonl` | 行式 JSON | `jsonl` | 批量结构化记录交换 |
| `*.json` | JSON 文档 | `json/dict` 或 `graph` | 图结构、配置、元数据 |
| `*.txt` | 纯文本 | `json/dict` (modality=text) | NLP 文本语料 |
| `media_refs.jsonl` | blob 引用 | `blob_ref` | 多模态对象存储引用 |

### 4.2 文本语料（text_corpus.txt）

5种文档模板，每篇200-500字：
1. **年报摘要**：营业收入、关联交易、审计风险信号
2. **监管问询**：证监会问询函、关注函、行政处罚
3. **股权结构**：股东持股、关联实体、实际控制人
4. **舆情报道**：舞弊信号、市场分析、负面情绪
5. **财务分析**：应收账款、存货、商誉、现金流、资产负债率

## 六、数据对齐层匹配

数据集设计支持 [aligner.py](../modules/shared/aligner.py) 的三层对齐：

### 6.1 实体对齐

数据集中跨源实体名称存在自然重叠（如"卓郎智能机械"在 ERP/银行/舆情三个 source 中出现），可验证 `EntityAligner` 的：
- USCC 硬匹配（`counterparty_uscc` 字段）
- 名称相似度软匹配（去后缀后"卓郎智能机械有限公司"→"卓郎智能机械"）
- 传递闭包合并（A~B, B~C → A~C）

### 6.2 时间对齐

数据集含多种时间格式，可验证 `TimeAligner`：
- `period`: "2025-06"（业务期间字符串）
- `event_time`: "2025-06-15T10:30:00"（ISO8601）
- `captured_at`: "2025-06-15T10:30:00"（媒体采集时间）
- `publish_date` / `event_date`: "2025-06-15"（日期）

### 6.3 模态对齐

数据集含同一实体的多模态记录（如"卓郎科技"同时出现在 records.jsonl 的 `counterparty` 和 text_corpus.txt 的文本中），可验证 `ModalAligner` 的跨模态融合。

## 七、数据再生与扩展

### 7.1 重新生成

```bash
# 在项目根目录执行
.venv\Scripts\python.exe demo\generate_synthetic_data.py
```

可通过修改 `generate_synthetic_data.py` 中的 `SIZE_BOOST` 参数调整数据量（当前 1.55x ≈ 1.07GB）。

### 7.2 验证数据

```bash
.venv\Scripts\python.exe demo\verify_data.py
```

### 7.3 扩展数据

如需增加真实数据源，可：
1. 在 `generate_synthetic_data.py` 的 `COMPANIES` / `PERSONS` / `COUNTERPARTIES` 中添加实体
2. 在 `TEXT_TEMPLATES` 中添加文本模板
3. 调整 `MODULE_SIZES` 增加特定模块的数据量
